Play a video by its UUID.

Secure video playback for Flutter, backed by the eSITE Video Service. Give the plugin a video UUID — it resolves the video through your backend, works out whether it is unprotected, Lite DRM or Full DRM, and plays it in a native fullscreen player on Android and iOS.

Overview

The whole integration

dart
// Once, at app start.
ESitePlayer.configure(
  baseUrl: 'https://api.myapp.com',
  tokenProvider: () async => auth.accessToken,
);

// Then, wherever you play something.
final controller = await ESitePlayerController.forVideo(videoId);
await controller.launchPlayer();

No manifest URLs, no license servers, no DRM branching in your app. The plugin handles HLS and DASH, AES-128 encryption and Widevine sessions, and reports everything back through three typed streams.

Architecture

How it fits together

The plugin never talks to the eSITE service directly. Your backend holds the tenant API key and makes the server-to-server call; the plugin authenticates to your backend with a token your app already has.

Why not call eSITE directly

The tenant API key authenticates at UPLOADER or higher — which includes upload and, for EDITOR/ADMIN, delete. It is not a read-only playback credential, and anything shipped in an APK or IPA is extractable. Do not pass an eSITE key through ESitePlayer.configure(headers: …) to shortcut the integration; that defeats the entire arrangement.

Protection

Three modes, resolved for you

The backend's drm_type decides which path the plugin takes.

drm_type Delivery What the player does Android iOS
none HLS Plays directly yes yes
lite HLS, AES-128 segments Player fetches the key from the playlist's key route — no DRM session yes yes
full DASH + license server Opens a Widevine session yes no

Lite DRM is standard HLS AES-128

Both ExoPlayer and AVPlayer handle it natively. That is why it needs no DRM configuration, no license server and no extra headers — the playback URL is token-authenticated in the URL itself, and the segment key is fetched by the player along the same path as the segments.

Full DRM on iOS

Full-DRM content is packaged as DASH + Widevine. AVPlayer plays neither. Supporting it on iOS requires the video service to also package CBCS fMP4 HLS and expose a FairPlay SPC/CKC endpoint plus an application certificate — that backend work is pending.

Until then forVideo() throws unsupportedOnPlatform for full-DRM videos on iOS rather than presenting a black screen. The FairPlay wiring is stubbed in ios/Classes/ESiteContentKeyManager.swift, ready for the certificate fetch and CKC exchange.

Setup

Quick start

1 — Configure once

dart
void main() {
  ESitePlayer.configure(
    baseUrl: 'https://api.myapp.com',      // your backend
    videoPath: '/videos/{id}/playback',    // default; override to match your routes
    tokenProvider: () async => auth.accessToken,
  );
  runApp(const MyApp());
}

tokenProvider is called per request, so a refreshed token is picked up without reconfiguring. Return null to send no Authorization header.

2 — Play by UUID

dart
final controller = await ESitePlayerController.forVideo(
  '4c2f5fdd-d88e-4d2b-b03d-039edef920a7',
  options: const ESitePlaybackOptions(
    autoPlay: true,
    preventScreenRecording: true,
    primaryColor: Color(0xFF6C63FF),
    secondaryColor: Colors.white,
  ),
);

controller.stateStream.listen((state) {
  if (state == ESitePlayerState.completed) {
    // Watched to the end.
  } else if (state == ESitePlayerState.closed) {
    // Dismissed early.
  }
});

controller.errorStream.listen((e) => report(e.message));

await controller.launchPlayer();

Call controller.dispose() when you are finished. A controller is bound to one video — play another by creating a new one.

3 — Handle resolution failures

dart
try {
  final controller = await ESitePlayerController.forVideo(videoId);
  await controller.launchPlayer();
} on ESitePlayerException catch (e) {
  switch (e.code) {
    case ESitePlayerErrorCode.unauthorized:
      await auth.refresh();
    case ESitePlayerErrorCode.videoNotReady:
      showMessage('Still processing — try again shortly.');
    case ESitePlayerErrorCode.unsupportedOnPlatform:
      showMessage('This video cannot be played on iOS yet.');
    default:
      showMessage(e.message);
  }
}

Integrate

What your backend must return

By default the plugin expects the eSITE videoDetail shape, so a backend that proxies the eSITE response straight through needs no mapping code.

json · lite or plain
{
  "id": "4c2f5fdd-d88e-4d2b-b03d-039edef920a7",
  "name": "Sample",
  "status": "ready",
  "drm_type": "lite",
  "playback_url": "https://…/master.m3u8?token=…",
  "renditions": []
}

For full DRM, eSITE never returns license material — the spec is explicit that “DRM key material is never returned” — so your backend must enrich the response:

json · full drm
{
  "drm_type": "full",
  "playback_url": "https://…/manifest.mpd?token=…",
  "license_server_url": "https://…/widevine",
  "entitlement_message": "…",
  "license_header_name": "X-Entitlement-Message"
}

license_header_name is optional and defaults to X-Entitlement-Message. A nested form is accepted too:

json · nested form
{ "drm": { "license_url": "…", "headers": { "Authorization": "Bearer …" } } }

Playback URLs expire

The service issues 6-hour tokens on the HLS playback endpoint and 15-minute presigned URLs for renditions and thumbnails. Resolve immediately before playing; never cache or persist a resolved source, which is a bearer credential for the content while valid.

Integrate

A different response shape

If your backend returns something else, supply a mapper:

dart
ESitePlayer.configure(
  baseUrl: 'https://api.myapp.com',
  tokenProvider: () async => auth.accessToken,
  mapper: (json) => ESiteResolvedSource(
    url: json['stream_url'] as String,
    streamFormat: ESiteStreamFormat.hls,
    drmType: ESiteDrmType.lite,
    title: json['title'] as String?,
  ),
);

Throwing inside the mapper surfaces as configurationError.

Playback control

The native players already provide full on-screen controls — play/pause, ±10s double-tap seek with a ripple animation, scrubber, and speed, quality and audio-track menus — so most apps never call these. They exist for custom UI and automation.

seekTo(Duration)Rejects negatives

Reference

Resolution types

ESiteDrmType

none, lite, full. parseDrmType(String?) parses case-insensitively and falls back to none for unknown values — the service's spec types drm_type as a bare string with no enum, so an unrecognised value must degrade safely.

ESiteResolvedSource

url, streamFormat, drmType, drm?, headers?, title?.

ESiteVideoDetail

Mirrors manager.videoDetail: id, name, status, drmType, playbackUrl, thumbnailUrl, renditions, plus raw for backend-specific fields. isReady treats a null status as ready; bestRendition picks the highest-resolution rendition with a packaged URL.

ESitePlaybackResolver

Pure and platform-agnostic, so it is fully unit-testable:

  • not ready → videoNotReady
  • none / lite → HLS, no DRM, no headers
  • full → DASH plus a license descriptor, falling back to the best rendition when playback_url is absent

Reference

Events

ESitePlayerState

StateMeaning
idleNothing loaded
initializingPlayer created, media being prepared
bufferingWaiting on data
readyReady to play
playing / pausedTransport state
completedThe media reached its end
errorPlayback failed
closedThe player was dismissed

completed and closed are distinct: one means watched to the end, the other abandoned. Earlier versions conflated them.

ESiteDrmEvent

licenseRequested, licenseAcquired or licenseFailed, with an optional message. Only emitted for full DRM — Lite DRM opens no session, so silence on this stream is expected and correct.

Wire contract

State, DRM and error values cross the platform channel as enum ordinals shared with the native players. Append new values only — reordering silently breaks the native contract.

Operate

Security

Screenshot and recording protection

CapabilityAndroidiOS
Block screenshots FLAG_SECURE not possible
Block screen recording FLAG_SECURE hidden while capturing
Block mirroring / AirPlay capture FLAG_SECURE hidden while capturing

Android's FLAG_SECURE is enforced by the window compositor and genuinely prevents capture. iOS offers no equivalent: the plugin observes UIScreen.isCaptured and hides the video layer and pauses playback while capture is active. Screenshots can only be detected after they are taken, never prevented.

Set expectations honestly

Do not present iOS screenshot protection as equivalent to Android's. If your content genuinely requires it, iOS cannot deliver it at any layer, and no plugin can change that.

What Lite DRM does and does not protect

Lite DRM protects content in transit and at rest in storage. It is not a DRM system: the key reaches the player in the clear over TLS, with no device binding, no output protection and no revocation. Use it where the threat model is casual copying, not determined extraction. Full DRM adds device binding, security-level enforcement and revocation.

Transport

All playback and license traffic must be HTTPS. Android surfaces cleartext attempts as networkError; iOS App Transport Security does the same. Do not add cleartext exemptions to make a staging environment work — terminate TLS there instead.

There is no gradle wrapper in android/ — build the Android side through Flutter, not ./gradlew.

The stub backend

The example app ships a stub backend (example/lib/stub_backend.dart) that serves videoDetail-shaped responses over loopback, so it runs with no credentials and no server of your own. It covers lite, plain, full-DRM, not-ready, no-playback-URL, not-found and unauthorized paths.

The stub cannot mint a presigned URL — that happens server-side behind the tenant API key. To exercise genuine Lite DRM decryption, fetch a real playback_url once and paste it into _placeholderHls in example/lib/main.dart.

SymptomCauseFix

Operate

Known limitations

  • Full DRM does not play on iOS. Pending FairPlay HLS packaging from the video service.
  • iOS cannot block screenshots. No API exists at any layer.
  • No live API response has been observed. Every eSITE endpoint returns 401 without the tenant key, so the drm_type string values are inferred from the OpenAPI description text. Parsing is deliberately tolerant.
  • The full-DRM license descriptor is not yet fixed. The resolver accepts both a flat and a nested shape; the backend team needs to settle on one.
  • The spec contradicts itself on playback_url for full-DRM videos — the endpoint description calls it a presigned DASH entry point, the field doc says it is null and to use rendition URLs. The resolver accepts either.
  • No Swift Package Manager support yet. CocoaPods only; Flutter emits a warning.
  • Playlists are single-item. next() / previous() are no-ops.
